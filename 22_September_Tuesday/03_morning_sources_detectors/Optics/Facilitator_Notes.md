- Bragg-crystal numbers (Si, V=160.1826 Å³) match the syntax already documented in this project's X-ray optics component notes.
- A [`hints/`](./hints/) folder with ready-made starter `.instr` files exists, covering the guide-building step of Exercise 1 (`exA2_mcstas_starter.instr`) and the crystal-geometry step of Exercise 2 (`exB2_mcxtrace_starter.instr`) — filenames unchanged from the old A2/B2 numbering, so cross-check the exercise sheet's step numbers if you're following along in the file's header comments, which still reference the old A1–A2/B1–B2 labels.
- The sheet keeps "the method, and how to read a change" (baseline → add one component → compare → explain → parameter scan, plus a shortened four-category taxonomy: geometrical / spectral / intensity loss / resolution-acceptance) up front, trimmed from the original six-category version — finite-sampling artefacts are folded into a one-line aside rather than a fifth bullet, since Exercise 3 of the Sources & Monitors sheet already covers Monte Carlo noise and binning in more depth.
- The guide-length scan (Exercise 1) and rocking-curve scan (Exercise 2) are still real `mcrun`/`mxrun` scan commands, not "run it a few times by hand". Syntax confirmed against a current `mcrun --help` (2026): `-N`/`--numpoints` with `par=min,max` for a single-parameter scan; `-M`/`--multi` for the cartesian-product grid of every scanned parameter, combined with `-N` given as a comma-separated list (one point count per parameter); `-L`/`--list` for explicit value lists; `--seeds=` to scan a range of seeds natively as its own dimension. Note: `--seeds=` cannot currently be combined into a *third* dimension alongside an `-M`/`-L` grid — this was flagged and removed from the PowderN sheet's optional extension, and the same limitation applies here if anyone asks about extending the guide-length/`m` grid with a seed sweep.
- The Data-export/Checkpoints on both exercises still flag that a scan is *many* samples, not one — this sheet's link to the per-sample metadata schema in [`Data_Generation_Pipeline.md`](../../../../Data_Generation_Pipeline.md) (link depth updated after the folder moved under `04_morning_sources_detectors/Optics/`); worth pointing participants at that document explicitly if the AI framing of the week hasn't come up yet by Tuesday morning.
