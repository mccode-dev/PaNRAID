# Facilitator Notes — Optics

Internal notes for whoever is running [`Exercises_Optics.md`](./Exercises_Optics.md); not intended for participants.

- Part A (A1–A3) and Part B (B1–B2) are the core material; A4 and B2′ are natural extensions for fast finishers or a follow-up session, matching the "pick two of the three: CRLs, KB mirrors, monochromators" framing on the last lecture slide — a CRL-focused exercise (following the worked Be/Al stack example on slide 9) would be a natural third addition later.
- Bragg-crystal numbers in Part B (Si, V=160.1826 Å³) match the syntax already documented in this project's X-ray optics component notes; the DCM arm/rotation pattern follows the lecture's own worked snippet directly.
- A [`hints/`](./hints/) folder with ready-made starter `.instr` files exists, covering Exercise A2 (McStas) and Exercise B2 Track 1 (McXtrace) only. Exercise A1, and Track 2's multilayer variant (B2′), are not covered by a starter file.
- The sheet now opens with an explicit statement of "the general method" (baseline → add one component → compare → explain → parameter scan) and a shared taxonomy of effect types (geometrical / spectral / intensity / resolution / acceptance-collimation / finite-sampling artefact), both added in response to reviewer feedback that the original version let participants assemble an instrument without being pushed to reason about *why* each addition changed the output. Every exercise's checkpoints now explicitly ask which taxonomy category explains an observed change — worth checking participants are actually using the taxonomy rather than skipping straight to "it changed" when discussing answers.
- A2's guide-length/`m` exploration and B2's rocking curve are now written as real `mcrun`/`mxrun` scan commands rather than "run it a few times by hand". The syntax is confirmed against a current `mcrun --help` (2026): `-N`/`--numpoints` with `par=min,max` for a single-parameter scan; `-M`/`--multi` to run the cartesian-product grid of every scanned parameter, combined with `-N` given as a comma-separated list (one point count per parameter); `-L`/`--list` for explicit value lists (numeric or string), including a `min:delta:max` range auto-expanded into a list; and `--seeds=` to scan a range of seeds natively. This is a comparatively recent `mcrun`/`mxrun` addition — older installations may only support the basic single-parameter `-N par=min,max` form, which is why the sheet still introduces that form first before the grid scan.
- The Data-export step on A2/B2 flags that a scan is *many* samples, not one — this is the Optics sheet's link to the per-sample metadata schema in [`Data_Generation_Pipeline.md`](../../../Data_Generation_Pipeline.md); worth pointing participants at that document explicitly if the AI framing of the week hasn't come up yet by Tuesday afternoon.
