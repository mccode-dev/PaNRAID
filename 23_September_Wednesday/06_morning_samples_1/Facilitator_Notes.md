# Facilitator Notes — PowderN

Internal notes for whoever is running [`Exercises_PowderN.md`](./Exercises_PowderN.md); not intended for participants.

- Parts A1/B1 and A2/B2 are intentionally minimal (3–4 components) for the baseline — the point is to get to a recognisable Debye-Scherrer pattern fast, not to build a realistic diffractometer on the first pass. A3/B3 and A4/B4 are optional extensions for fast finishers or a Day-4 bridge.
- Real bundled reference files used in the exercise sheet: `Al.laz` and `LaB6.cif` are both standard example materials already used elsewhere in the McStas/McXtrace example suites (the `Tests_samples/Test_PowderN` McXtrace example is exactly the LaB₆-via-CIF case shown here, and produces the `PowderN.png` Debye-Scherrer image already referenced in this project's samples notes).
- The exact McStas syntax for pointing `PowderN` at an NCrystal material (A2, step 2) is left as a doc-lookup/verification step deliberately — worth confirming against the installed McStas version before the session, and adjusting the exercise text once confirmed.
- A [`hints/`](./hints/) folder with ready-made starter `.instr` files exists, covering the A1/B1 baseline only (both codes). A2/B2 (the NCrystal/CIF-vs-table comparison, which is the actual point of that step) and the A3/B3 optics-attachment option are not covered by a starter file.
- New: A4/B4 ("Multi-dimensional scans: wavelength/energy × material") were added in response to a reviewer request for `mcrun`/`mxrun`-driven multi-dimensional scans. Both hint starter instruments were updated to expose `reflections` as a `string` instrument parameter specifically to support this — check that change compiles cleanly against your installed McStas/McXtrace version before the session, since a `string`-typed instrument parameter combined with command-line scanning is exactly the kind of detail worth a dry run beforehand.
- A4/B4 uses `mcrun`/`mxrun`'s current `-M`/`-L` scan support directly (confirmed against a current `mcrun --help`, 2026): `-L`/`--list` takes an explicit value list for any parameter — numeric or string — with a `min:delta:max` range auto-expanded into its own list, and `-M`/`--multi` runs the cartesian product across every scanned parameter, so a single command now produces the full wavelength/energy × material grid (no shell loop needed). This is a comparatively recent addition — worth confirming `-M`/`-L` actually exist in the group's installed version via `mcrun --help`/`mxrun --help` before the session; on an older install, the exercise's step-1 single-parameter scan (`-N par=min,max`) still works, but the grid step will need falling back to a manual shell loop over materials (the pattern this sheet used before the tool was confirmed to support it natively).
- A4/B4's "optional extension" (deliberately confounding material and energy) is a good discussion prompt even for groups that don't have time to build the dataset — it's the clearest concrete illustration in this school of the shortcut-learning risk described in [`Data_Generation_Pipeline.md`](../../../Data_Generation_Pipeline.md).
